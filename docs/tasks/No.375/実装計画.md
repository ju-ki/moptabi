# No.375 待ち時間を表示する 実装計画

対象: `feature375`（`dev` = eaccd2d をマージ済み）
前提: [調査報告](./No.375_待ち時間の表示_調査報告.md) の案A（PR #446 レビューで決定）

## 1. 要件

- 最寄駅経由（移動手段ID 4）の区間で、駅に着いてから発車するまでの待ち時間を表示する
- 対象画面: 作成/更新のプレビュー、プラン詳細
- 0 分も「待ち 0分」と表示する。値が無い（既存プラン・最寄駅経由でない区間）ときは表示しない
- 対象外: スポット追加を促す強調表示、移動手段の段の内訳表示

## 2. 方針

プランニングで計算した待ち時間を最寄駅テーブルに保存し、詳細画面は保存した値をそのまま表示する。表示側では計算しない。

## 3. 変更内容

### 3.1 DB（backend）
| ファイル | 変更 |
|---|---|
| `backend/src/db/schema.ts` | `planSpotNearestStation` と `planLocationNearestStation` に `waitingTime: integer()`（nullable）を追加 |
| `backend/drizzle/0017_add_nearest_station_waiting_time.sql` | `bun run db:generate` で生成（`ALTER TABLE ... ADD COLUMN "waitingTime" integer` ×2） |

既存行は `null`（=表示しない）になるため、データ移行は不要。

### 3.2 共通の型
| ファイル | 変更 |
|---|---|
| `packages/shared-types/src/nearestStation/schema.ts` | `NearestStationSchema` に `waitingTime: z.number().int().min(0).optional()` を追加 |

### 3.3 API（backend）
| ファイル | 変更 |
|---|---|
| `backend/src/services/trip.ts` | 更新時の出発地・目的地・スポットの最寄駅 insert / upsert に `waitingTime` を追加。取得時の変換（`convertPlanSpotData` / `convertPlanLocationData`）で `waitingTime: nearestStation.waitingTime ?? undefined` を返す（null のときはキーを返さない） |
| `backend/src/services/spot.ts` | `createPlanSpot` の最寄駅 insert に `waitingTime` を追加 |
| `backend/src/services/planLocation.ts` | 出発地・目的地作成時の最寄駅 insert に `waitingTime` を追加 |

### 3.4 プランニング（frontend）
| ファイル | 変更 |
|---|---|
| `frontend/src/lib/planning.ts`（`executePlanning` の書き戻し部分） | 最寄駅経由が選ばれた区間だけ `waitingTime` を書き戻す。最寄駅経由以外（徒歩などを選んだ、片側だけ最寄駅）の区間では `waitingTime` を `undefined` にし、前回の値が残って保存されないようにする |

移動手段を切り替えた直後は再プランニングするまで保存できない（`CreatePlanButton.tsx` の dirty チェック）ため、保存される値は常にプランニング結果と一致する。

### 3.5 表示（frontend）
| ファイル | 変更 |
|---|---|
| `frontend/src/components/travel-plan/nearestStation/RouteSummaryNearestStation.tsx` | 乗車駅と電車/バスの行の間に「待ち X分」の行を追加（`data-testid="route-summary-waiting-time"`）。プレビューの `SpotDetailCard` / `DepartureDetailCard` から使われる |
| `frontend/src/components/NearestStationDetail.tsx` | 「発車」の前に「待ち X分」バッジを追加（`data-testid="nearest-station-waiting-time"`）。詳細画面の `SpotInfoCard` / `DepartureInfoCard` から使われる |

どちらも `typeof waitingTime === 'number'` のときだけ表示する（0 を含む）。

### 3.6 デザイン資料
| ファイル | 変更 |
|---|---|
| `docs/pages/plan-detail.md` | 出発地カード・スポットカードの最寄駅項目に「最寄り駅での待ち時間」を追加 |
| `docs/pages/plan-create.md` | ルート概要（最寄駅経由）の表示項目に「待ち時間」を追加 |

## 4. テスト（TDD）

| ファイル | 追加するテスト |
|---|---|
| `backend/src/tests/trip.service.spec.ts` | 作成時に `waitingTime` が保存されること（0 分を含む）／詳細取得で返ること／未設定なら返さないこと／更新で上書きされること |
| `backend/src/tests/libs/data.ts` | `mockPlanDataWithNearestStation` に `waitingTime` を追加 |
| `frontend/src/tests/lib/planning/nearest-station.spec.ts` | 徒歩を選んだ区間では `waitingTime` が `undefined` になること |
| `frontend/src/tests/components/travel-plan/nearestStation/RouteSummaryNearestStation.spec.tsx` | 「待ち X分」が表示されること／0 分も表示されること／未設定なら表示されないこと |
| `frontend/src/tests/components/SpotInfoCard.spec.tsx`, `DepartureInfoCard.spec.tsx` | 詳細画面で「待ち X分」が表示されること／未設定なら表示されないこと |

## 5. 影響範囲

- 最寄駅情報を保存・取得する API（作成・更新・詳細取得）。レスポンスに任意項目が増えるだけで既存の項目は変わらない
- マイグレーションは列追加のみ。staging / production は既存の手順（`db:migrate:*`）で反映する
