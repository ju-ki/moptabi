## 実装計画

### 🔍 根本原因分析

| 項目 | 現況 | 問題点 |
|-----|------|--------|
| **スナップショット保存** | `setPlanningResult` で実行 | JSON.stringify/parse が undefined を無視するため、最寄駅情報の一部がロストされる可能性 |
| **復元ロジック** | `restorePlannedSpots` で実行 | 保存時にロストした情報は復元できない |
| **テストケース** | 3つのテスト存在 | ❌ 期待結果の8項目をチェックしていない（検証が不十分） |
| **クローン処理** | `JSON.parse(JSON.stringify())` 使用 | 型安全でない可能性、undefined フィールドがロスト |

#### **ステップ2: クローン関数の改善**
**ファイル**: `frontend/src/lib/plan.ts`

**改善内容**:
- 現在: `JSON.parse(JSON.stringify())` （undefined がロスト）
- 修正案: **構造化クローン関数を実装**

```typescript
/**
 * 最寄駅情報を含む ExtendSpotType を完全にクローン
 * JSON.stringify では undefined がロストするため、明示的に処理
 */
function cloneSpots(spots: ExtendSpotType[]): ExtendSpotType[] {
  return spots.map(spot => ({
    ...spot,
    nearestStation: spot.nearestStation ? { ...spot.nearestStation } : undefined,
  }));
}

/**
 * 最寄駅情報を含む ExtendPlanLocationType を完全にクローン
 */
function cloneDepartureAndDestination(
  depAndDest: ExtendPlanLocationType
): ExtendPlanLocationType {
  return {
    ...depAndDest,
    nearestStation: depAndDest.nearestStation 
      ? { ...depAndDest.nearestStation }
      : undefined,
  };
}
```

**理由**:
- ✅ スプレッド演算子で undefined も保持
- ✅ nearestStation 内の全フィールド（8項目）を保持
- ✅ JSON.stringify の制限を回避
- ✅ 型安全
