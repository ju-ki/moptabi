# No.439 カレンダー選択のレイアウトが動的になってしまっている 実装計画

調査対象: `dev` (0a82bda)

## 1. 要件（Issue #439）

- 開始日・終了日を選ぶとき、ヒントのメッセージによってカレンダーの幅が変わり押しづらい
- メッセージの幅に関わらず、カレンダーの幅は固定とする

## 2. 原因

`frontend/src/components/DateRangePicker.tsx`

- ポップオーバーが `PopoverContent className="w-auto p-0"` のため、幅が中身の最大幅で決まる。
- 中身はヒント（`getHintMessage()`）とカレンダー。ヒントは選択状態で4種類に切り替わり、文字数が 16〜29 文字と違う。
- カレンダー1か月分の幅は 7列 × 36px（`w-9`）+ 左右 padding 24px（`p-3`）= 276px。ヒントが長いとき（例:「終了日を選ぶか、同じ日を選んで「日帰り」にしてください」≒ 29文字 × 12px + 24px ≒ 372px）はポップオーバーがヒントに合わせて広がる。
- カレンダー（`ui/calendar.tsx`）は前月/翌月ボタンが `absolute left-1` / `absolute right-1` のため、ポップオーバーの幅が変わるとボタンの位置が動く。日付のグリッドは左寄せのままなので、選択のたびに見た目が崩れる。

| 選択状態 | ヒント | ポップオーバーの幅 |
| --- | --- | --- |
| 未選択 | 開始日を選んでください（最大 7 日間） | カレンダー幅（実測 278px） |
| 開始日のみ | 終了日を選ぶか、同じ日を選んで「日帰り」にしてください | ヒント幅（実測 354px） |
| 日帰り | 同じ日を選ぶと選択を解除できます | カレンダー幅（実測 278px） |
| 複数日 | 日付を減らすには、開始または終了日を選択してください | ヒント幅（実測 342px） |

## 3. 方針

`DateRangePicker.tsx` だけを変更する。共通の `ui/popover.tsx` / `ui/calendar.tsx` は他画面でも使っているため変えない。

ヒントは1行で表示したまま、ポップオーバーの幅を「最長のヒント」に揃え、カレンダーをその幅いっぱいに広げる（2026-10-08 レビューで、2行に折り返す案から変更）。

1. **全ヒントを重ねて描画**: 4種類のヒントを CSS Grid の同じセル（`col-start-1 row-start-1`）に重ねて描画し、現在の文言以外は `invisible` + `aria-hidden` にする。
   - ポップオーバーの幅は常に最長のヒント（「終了日を選ぶか、同じ日を選んで「日帰り」にしてください」）で決まるため、選択状態が変わっても幅が変わらない。
   - px を直書きしないので、端末のフォントで文字幅が変わっても追従する。
   - 画面幅が足りない端末では4つとも同じように折り返すため、高さも状態によらず一定になる。
2. **カレンダーを幅いっぱいに広げる**: `Calendar` に `className="[&_td]:flex-1 [&_td_button]:w-full [&_th]:flex-1"` を渡し、曜日・日付の列を均等に広げる（日付が左に寄り、右側が空くのを防ぐ）。
3. `PopoverContent` は `w-auto` のまま。

実測（375px 幅）: 修正前は状態によって 278 / 342 / 354px と変わっていたのが、修正後は 4 状態とも 354px。

## 4. 実装ステップ（TDD）

1. **テスト追加（Red）** `frontend/src/tests/components/DateRangePicker.spec.tsx` に「レイアウト」の describe を追加
   - jsdom ではレイアウト計算ができないため、描画構造とクラス名で検証する。
   - 未選択 / 開始日のみ / 日帰り / 複数日 の各状態でポップオーバーを開き、
     - 4種類すべてのヒントが `col-start-1 row-start-1` で描画されていること
     - 現在のヒントだけが表示され、他は `invisible` かつ `aria-hidden="true"` であること
     - 4状態でポップオーバーのクラス名が同じであること
2. **実装（Green）**: `DateRangePicker.tsx` のヒント部分と `Calendar` の `className` を変更
3. **確認**: `pnpm run lint` / `pnpm run typecheck` / `pnpm run format:check` / フロントのテスト / ブラウザでの幅の実測
