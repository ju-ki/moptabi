# No.409 予定日のデフォルト値に翌日の日付を設定する 実装計画

調査対象: `dev` (c02ea8e)

## 1. 要件（Issue #409）

- プラン作成画面を開いた時点で、予定日の **開始日** に「現在日付の翌日」を入れておく
- 終了日は空のまま（ユーザーが終了日、または同じ日を選んで日帰りにする）

## 2. 現状

- 予定日は `useStoreForPlanning` の `startDate` / `endDate` で管理している。初期値は `createPlanningInitialState()`（`frontend/src/lib/plan.ts:81-103`）で `''`。
- 作成画面 `frontend/src/app/plan/create/page.tsx:67-70` はマウント時に `fields.resetPlanningStore()` を呼んでいる。
- 編集画面 `frontend/src/app/plan/[id]/edit/page.tsx:47-51` も `resetPlanningStore()` の後に `setRangeDate` で既存プランの日付を入れている。
- 保存後 `frontend/src/components/CreatePlanButton.tsx:158` でも `resetPlanningStore()` している。

## 3. 方針

ストアの初期値（`createPlanningInitialState`）は変えず、**作成画面のマウント時だけ** 開始日をセットする。

- ストア初期値を変えると、編集画面のリセット直後や保存後のリセットでも翌日が入ってしまい、影響範囲が広がるため。
- ストアのモジュール読み込み時に日付を固定すると、日をまたいで画面を開いたときに古い日付になるため、マウント時に毎回計算する。

### 追加する関数

`frontend/src/lib/utils.ts`

```ts
/**
 * 基準日の翌日を YYYY-MM-DD 形式（ローカル時刻）で返す。
 * @param baseDate 基準日（省略時は現在日時）
 */
export const getTomorrowDateString = (baseDate: Date = new Date()): string
```

- `new Date(y, m, d + 1)` で計算し、`toLocaleDateString('sv-SE')` で整形（既存の `getDatesBetween` / `DateRangePicker` と同じ形式）。
- 月末・年末・うるう年をまたいでも正しく翌日になる。

### 作成画面の変更

`frontend/src/app/plan/create/page.tsx` のマウント時の `useEffect`

```ts
useEffect(() => {
  fields.resetPlanningStore();
  fields.setFields('startDate', getTomorrowDateString());
}, []);
```

- 開始日だけが入り終了日が空の状態では `getDatesBetween` が `[]` を返すため、プラン（日別タブ）は作られない。従来の「開始日だけ選んだ状態」と同じ挙動。
- `DateRangePicker` は開始日のみの状態に対応済み（ボタンに開始日を表示、カレンダーは開始日の月を表示、ヒントは「終了日を選ぶか、同じ日を選んで日帰り」）。変更なし。
- 終了日未選択のまま保存しようとした場合は、既存の `CreatePlanButton.tsx:40-41` のバリデーション（「プランの日付を入力してください」）が出る。変更なし。
