# No.168 現在地登録の秘匿化 実装計画

- Issue: https://github.com/ju-ki/moptabi/issues/168
- 調査報告: `docs/tasks/No.168/No.168_現在地登録の秘匿化_調査報告.md`（PR #443 のレビュー反映済み）
- 方針: 案A（サーバー側でのアプリ層暗号化、AES-256-GCM）

## 1. ゴール
- Neon のコンソールや `DATABASE_URL` から DB を直接見ても、ユーザーの地点の座標と、そこから位置を推測できる情報が読めない状態にする。
- API のリクエスト・レスポンスの形は変えない。フロントエンドと `packages/shared-types` は変更しない。

## 2. 暗号化の対象

| テーブル | 暗号化する項目 | 保存先（新カラム） | 平文で残す項目 |
|---|---|---|---|
| `UserLocation` | `latitude`, `longitude`, `label` | `encryptedData`（JSON を暗号化） | `name`, `usageCount`, `isDefault` |
| `UserLocationNearestStation` | `placeId` | `encryptedPlaceId` | `stationType` |
| `PlanLocation` | `latitude`, `longitude`, `travelTime` | `encryptedData`（JSON を暗号化） | `name`, `time`, `locationType`, `transportMethodId` |
| `PlanLocationNearestStation` | `placeId` | `encryptedPlaceId` | `stationType`, `transitTime`, `scheduledDepartureTime`, `memo` |
| `PlanSpot`（各プランの最後のスポット） | `travelTime`（最後のスポット → 目的地） | 目的地の `PlanLocation.encryptedData.travelTime` に移す | 最後のスポットの `PlanSpot.travelTime` は 0 で保存 |

- 地点名（`name`）は平文のままにする（レビューで合意済み）。
- 最後のスポットから目的地までの移動時間は、PR #443 で推奨した「目的地側に移して暗号化」を採用する。API では従来どおり最後のスポットの `travelTime` として返すため、移し替えはバックエンド内で完結する。

## 3. 暗号化の仕様
- 方式: AES-256-GCM（Web Crypto の `crypto.subtle`。Cloudflare Workers / Bun の両方で動く）
- 鍵: 環境変数 `LOCATION_ENCRYPTION_KEY`（32 バイトを base64 にしたもの）
  - 本番・ステージング: `wrangler secret put LOCATION_ENCRYPTION_KEY`
  - ローカル: `backend/.dev.vars` と `backend/.env`
  - テスト: CI で `.env.test` に固定のテスト用の鍵を書き出す
- 保存形式: `v1:<IV の base64>:<暗号文+認証タグの base64>`
  - 先頭の `v1` は鍵のバージョン。将来鍵を入れ替えるときは `v2` を追加し、復号時にバージョンで鍵を選ぶ。
  - IV は暗号化のたびに 12 バイトの乱数を作る。同じ座標でも毎回違う暗号文になる。
- 鍵が設定されていない場合は、起動時ではなく最初の暗号化・復号の時点で 500 エラーにする（`console.error` で「鍵が未設定」とだけ出し、値はログに出さない）。

### 4-2. スキーマ・マイグレーション
- `backend/src/db/schema.ts`
  - フェーズ 1: `userLocation` / `planLocation` に `encryptedData: text()`（null 許容）、`userLocationNearestStation` / `planLocationNearestStation` に `encryptedPlaceId: text()`（null 許容）を追加する。既存の `latitude` / `longitude` / `label` / `travelTime` / `placeId` は `.notNull()` を外す。
  - フェーズ 2: 平文のカラムを削除し、新カラムを `.notNull()` にする。
- `backend/drizzle/*.sql`: 各フェーズで `bun run db:generate` で生成する（手修正しない）。

### 4-3. サービス層
| ファイル | 変更内容 |
|---|---|
| `backend/src/services/userLocation.ts` | `getUserLocationList`（9 行目〜）は復号して従来の形で返す。`createUserLocation`（55-73 行目）と `updateUserLocation`（124-155 行目）は暗号化して保存する。更新で一部の項目だけ送られた場合は、既存の値を復号して合成してから暗号化する |
| `backend/src/services/planLocation.ts` | `createPlanLocation`（29-55 行目）、`createOrUpdatePlanLocation`（155-204 行目）は暗号化して保存する。`getPlanLocationCandidates`（65-146 行目）は復号して返す。引数に `cipher` を追加する |
| `backend/src/services/trip.ts` | `createTrip`（40 行目〜）と `updateTrip`（126 行目〜、出発地・目的地の更新 181-276 行目、プラン追加 380-397 行目）は、最後のスポット（`order` が最大）の `travelTime` を目的地の暗号化 JSON に入れ、`PlanSpot` には 0 を保存する。`getTripDetailById`（444 行目〜）と `convertPlanLocationData`（536 行目〜）は復号し、目的地の `travelTime` を最後のスポットの `travelTime` に戻して返す（目的地自体の `travelTime` は従来どおり 0） |
| `backend/src/services/spot.ts` | 変更なし。`trip.ts` の `moveLastSpotTravelTimeToDestination` で最後のスポットの `travelTime` を 0 にしてから `createPlanSpot` に渡す |
| `backend/src/index.ts` | `Bindings` 型に `LOCATION_ENCRYPTION_KEY` を追加し、`c.env` の鍵を `configureLocationEncryptionKey` で設定するミドルウェアを追加する。サービスは `getLocationCipher()` で鍵を取得するので、コントローラーは変更しない |

- フェーズ 1 の読み出しは「`encryptedData` があれば復号、無ければ平文カラムを使う」とする。一括変換スクリプトを実行するまでの間も、既存データを表示できるようにするため。フェーズ 2 でこのフォールバックを削除する。
- 更新時は平文カラムを NULL にする。一括変換前のデータも、更新した時点で暗号化に置き換わる。
- 「最後のスポット」は `order` が最大のスポット（同じ `order` なら配列の後ろ）。移し替え元のスポットID を目的地の暗号化 JSON（`lastSpotId`）に入れ、読み出し時はそのスポットに戻す。
- `createOrUpdatePlanLocation` で他人の・存在しない `planLocationId` を指定した場合は 404 にする（従来は何も更新せず空のレスポンスを返していた）。

## 5. 既存データの一括変換（`backend/src/scripts/encrypt-locations.ts`）
- 実行: `DATABASE_URL=... LOCATION_ENCRYPTION_KEY=... bun run src/scripts/encrypt-locations.ts`（`package.json` に `db:encrypt-locations` を追加する）
- 処理:
  1. `encryptedData IS NULL` の `UserLocation` を 100 件ずつ読み、暗号化して保存する。
  2. `encryptedData IS NULL` の `PlanLocation` をプラン単位で読む。目的地の行は、そのプランの最後のスポットの `PlanSpot.travelTime` を `travelTime` として暗号化し、同じトランザクションで `PlanSpot.travelTime` を 0 にする。
  3. `encryptedPlaceId IS NULL` の最寄駅の行を暗号化する。
  4. 最後に件数を表示する（変換した件数・残り件数）。座標などの値は出力しない。
- `IS NULL` を条件にしているので、途中で止まっても再実行で続きから処理できる。

## 6. リリース手順
1. 鍵を作り、本番・ステージングの Workers Secret と GitHub Secret（ステージングプレビュー用）、各自の `.dev.vars` に設定する。鍵は 1Password 等にも保管する（失うと復元できないため）。
2. フェーズ 1 をデプロイする（マイグレーション → Workers デプロイ）。この時点で新規の保存は暗号化され、既存データは平文のまま読める。
3. 本番・ステージングで一括変換スクリプトを実行し、残り件数が 0 であることを確認する。
4. フェーズ 2 をデプロイする（平文カラムの削除とフォールバックの削除）。
- `.github/workflows/staging-preview.yml`（72-81 行目）で Secret を書き出す箇所に `LOCATION_ENCRYPTION_KEY` を追加する。
