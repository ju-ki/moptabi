# No.229 移動手段の個別設定機能

## ステータス
`実装中` （2026-04-21 要件確定・設計完了）

---

## 課題背景

* 現状一つの交通手段しか設定できないため、計画が立てづらい
* 滞在時間と移動時間の関係性がおかしい（各スポットを0分で移動していることになっている）
* 公共交通機関を利用するユーザーは、最寄駅・バス停の情報がないと思いの外遠くて計画が頓挫してしまう
* スポットが被っていると、スポット間のルート関係が見づらい

---

## 要件

| # | 要件 | 優先度 |
|---|------|--------|
| 1 | 最寄りのバス停や駅を表示する | 高 |
| 2 | 移動手段ごとのルートや時間を表示して、ユーザー側で設定できるようにする | 高 |
| 3 | 出発地と目的地の出発時間・到着時間を定義する | 高 |
| 4 | 個別スポットの滞在時間と優先順位を設定できるようにする | 高 |
| 5 | プランニング時に複数の移動手段を提示し、ユーザーが選択できるようにする | 中 |
| 6 | 目的地の到着時間を超える場合は警告を表示する（登録は可能） | 中 |
| 7 | ルートをクリックすると該当スポットを強調する | 低 |
| 8 | 出発時間の逆算機能 | 低 |

## 機能要件

### DBの定義変更（詳細はDB設計書参照）

#### 変更テーブル

| テーブル | 変更種別 | 内容 |
|---------|---------|------|
| `PlanLocation` | カラム追加 | `time VARCHAR(5)` — 出発時間または到着時間（HH:MM形式） |
| `PlanSpot` | カラム追加 | `stayDuration INTEGER` — 滞在時間（分単位） |
| `NearestStation` | 廃止 | `PlanSpotNearestStation` に統合（Spotテーブルが廃止のため） |

#### 新規テーブル

| テーブル | 目的 |
|---------|------|
| `PlanSpotNearestStation` | PlanSpot単位で最寄駅（Google Place ID + 種別）を管理 |
| `SpotRoute` | PlanSpot間の移動情報（手段・時間・出発時刻・メモ）を管理 |

---

### 最寄駅の取得方法

1. スポットの緯度経度で Google Places NearbySearch を呼び出す
2. プランニングボタン押下時に「最寄駅を取得するスポット」をユーザーが選択する
3. 複数候補がある場合はユーザーが選択（デフォルトは距離が最も近い駅）
4. 選択結果を `PlanSpotNearestStation` にプラン単位で保存する

---

### データフロー概要（電車移動の例）

```
[出発地 PlanLocation]
   time: "09:00"（出発時間）
        |　※移動時間はAPI呼び出し時に格納
[スポットA PlanSpot]
   stayDuration: 60分
   PlanSpotNearestStation: placeId=XXX（A駅, TRAIN）
        | ※移動時間はAPI呼び出し時に格納
  [SpotRoute A→B]
   transportType: TRAIN
   fromNearestStationId: A駅
   toNearestStationId: B駅
   waitingTime: 5分
   transitTime: 20分
   scheduledDepartureTime: "10:05"（ユーザー設定）
        | ※移動時間はAPI呼び出し時に格納
[スポットB PlanSpot]
   stayDuration: 90分
   PlanSpotNearestStation: placeId=YYY（B駅, TRAIN）
        | ※移動時間はAPI呼び出し時に格納
[目的地 PlanLocation]
   time: "18:00"（到着時間）
```

### プラン作成機能

#### FR-1: 最寄駅のバス停または駅表示

- プランニング後に表示されるマップ・カードに最寄駅を表示する
- バス停（BUS）と鉄道駅（TRAIN）は区別して表示する
- 最寄駅の詳細情報（名前・歩行時間）はGoogle Places APIから都度取得する（No.230準拠、DBには保存しない）
- 出発地・目的地・スポットの最寄駅をAPI送信する際は、`nearestStation.placeId` と `nearestStation.stationType` を必須で送る
   - `stationType` は `BUS` / `TRAIN` / `OTHER` のいずれか

#### FR-2: 移動手段ごとのルート提案・設定機能

- 日毎に検索対象の移動手段（WALK / CAR / TRAIN / BUS / OTHER）を選択してプランニングを実行する
- プランニング後、各スポット間の移動手段ごとのルート・距離・時間を表示し、ユーザーが選択できるようにする
- 順番や緯度経度を考慮して「推奨」ラベルを付与する
- スポット間の移動アイコンまたはマップ上のルートをクリックすると、該当ルートとスポットを強調表示する

#### FR-3: 出発時間 / 到着時間の設定機能

- 出発地（`DEPARTURE`）: 出発時間を設定する
- 目的地（`DESTINATION`）: 到着時間を設定する
- 目的地の到着時間を超える場合、以下の案内を含む警告を表示する（登録は可能）
  - 出発時間を何分早める必要があるか
  - 各スポット合計で何分滞在時間を短縮する必要があるか

#### FR-4: 滞在時間と移動時間の調整機能

- 現在のガントチャートによる滞在時間の設定は**廃止**
- 代わりに各スポットに `stayDuration`（分）と回る順番（`order`）を設定できるようにする
- FR-2で算出した移動時間（`SpotRoute.transitTime`）をもとに滞在時間を補正する

---

### プラン詳細画面

#### FR-1: 最寄駅のバス停または駅表示

- スポット一覧に最寄駅を表示する（名前・種別・歩行時間）
- 詳細情報はフロントエンドでGoogle Places APIから取得する

#### FR-2: 移動手段ごとのルート表示

- スポット間の移動アイコンまたはマップ上のルートをクリックすると、該当ルートとスポットを強調表示する

#### FR-3: 出発時間 / 到着時間の表示

- 出発地と目的地それぞれに設定時間を表示する
- 到着時間を超える場合は警告バナーを表示する

## 実装方針

### バックエンド

| 対象 | 内容 |
|------|------|
| DBスキーマ | `PlanLocation.time` / `PlanSpot.stayDuration` 追加、`PlanSpotNearestStation` / `SpotRoute` 新規作成 |
| API | `POST /trip/create` に一括登録データを内包（専用CRUDエンドポイントは今回作成しない） |
| NearestStation詳細 | DBには保存しない。フロントエンドがPlace IDをもとにGoogle APIで取得 |

### フロントエンド

| 対象 | 内容 |
|------|------|
| プラン作成画面 | 移動手段選択UI、最寄駅選択ダイアログ、出発/到着時間入力、滞在時間入力 |
| プラン詳細画面 | SpotRoute表示、最寄駅表示、時間超過警告バナー |
| Google Places API連携 | 最寄駅詳細（名前・歩行時間）をPlace IDで都度取得 |

---

## 実装順序

1. DBスキーマ変更 + マイグレーション（test環境）
2. バックエンド実装（`POST /trip/create` 内で SpotRoute・PlanSpotNearestStation を一括保存）
3. バックエンドテスト（スキーマ単体 → `trip/create` 経由の統合テスト）
4. フロントエンド実装（プラン作成 → 詳細画面）
5. 統合確認
