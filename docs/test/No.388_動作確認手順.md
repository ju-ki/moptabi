# No.388 プランニングアルゴリズムの見直し 動作確認手順

- 対象: `docs/tasks/No.388_実装計画.md` の実装（feature388）
- 処理の流れ: `docs/tasks/No.388_プランニング処理フロー.md`
- 自動テスト（`pnpm run test`）で確認できない、画面上の操作と表示を確認するための手順。各ケースの「結果」欄に OK / NG と気づいたことを記入する。

## 0. 準備

1. `docs/ローカル開発環境起動手順.md` に従って DB・バックエンド・フロントエンドを起動し、ログインする。
2. `/plan/create` を開き、タイトルと日程（1 日）を入力する。
3. 以降のケースは、特に断りがなければ次の条件から始める。
   - 出発地: 東京駅周辺の地点、出発時間 09:00
   - 目的地: 品川駅周辺の地点、到着時間 18:00
   - 移動手段: 徒歩・自転車・車をすべてチェック
   - スポット: 2 件（例: 浅草寺、上野恩賜公園）。互いに 1.5km 以上離れているもの
4. 「（日付）のプラン作成」ボタンを押すとプランニングが走り、右側のプレビューに結果と「警告メッセージ一覧」が表示される。

用語:
- **候補ボタン**: プレビューの各区間（出発地 → スポット1 など）の移動手段の横に並ぶ、他の移動手段のボタン。押すと移動手段が切り替わる。
- **最寄駅の設定**: 左側のスポット設定カードの「最寄駅を使用」トグルを on にし、プルダウンから駅を選ぶ。出発地・目的地は最初・最後のスポットのカードの上下にある最寄駅の欄で設定する。

## 1. 最寄駅経由と他の移動手段の切り替え（B1）

| No | 手順 | 期待結果 | 結果 |
| --- | --- | --- | --- |
| 1-1 | 出発地とスポット1 の両方に最寄駅を設定し、プラン作成 | 出発地 → スポット1 の移動手段が「電車/バス」になる。候補ボタンに徒歩・自転車・車が並ぶ | |
| 1-2 | 1-1 のあと、候補ボタンで「車」に切り替える | 移動手段が車になる。候補ボタンに「電車/バス」が表示される。整合性チェックが「スポット情報が変更されています」になる | |
| 1-3 | 1-2 のあと、プラン作成 | 移動手段は車のまま。**候補ボタンに「電車/バス」が残っている**。所要時間とスポットの滞在時刻が車の時間で計算されている | |
| 1-4 | 1-3 のあと、候補ボタンで「電車/バス」に戻してプラン作成 | 移動手段が電車/バスに戻り、所要時間が 1-1 と同じになる（発車時間候補を変えていない場合） | |
| 1-5 | スポット1 → スポット2、スポット2 → 目的地の区間でも 1-1〜1-4 を行う | 各区間で同じ結果になる | |
